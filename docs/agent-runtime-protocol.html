Runtime authority and scope

This protocol describes the additive v2.2 text-agent runtime. Existing v2.1 schemas, benchmarks, source snapshots, runs, and reports remain immutable legacy artifacts and are replayed with their frozen source snapshot rather than converted.

Filing verification, not autonomous audit. The runtime may calculate registered metrics, extract filing text, check citations, and safely refuse. It cannot issue an audit opinion, perform a statutory audit, make professional-judgment conclusions, contact an external party, or attest that a filing is true or complete.
IMPLEMENTED

Trust and visibility boundary

Model-visible

  • Sanitized AgentTaskInputV2.2.
  • The complete ordered context pack.
  • Zero or four approved, same-family few-shot examples.
  • Only capability-agent and narrative-hybrid tool observations.
  • Only allowlisted repair-safe diagnostics.

Never model-visible

  • gold.jsonl, expected answers, and refusal labels.
  • Verifier-only recomputation and replay results.
  • Credentials, environment capture, local sibling files, or network services.
  • Target-sensitive verifier details and raw exceptions.

Instructions found inside a task, filing, or evidence chunk are untrusted data. They never supersede the system prompt, operation registry, runtime policy, or verifier.

IMPLEMENTED

Case preconditions

  1. Validate the v2.2 task and recursively reject gold-like fields.
  2. Resolve its exact registry binding: task type, one operation, argument schema, observation schema, terminal schema, and refusal codes.
  3. Verify corpus, benchmark, filing, task, and evidence membership and hashes.
  4. Sanitize prompt-visible strings and identify hostile embedded instructions.
  5. Construct and hash the complete context before deriving the run ID.

A text task named vlm_diagnostic, a wrong operation, an unknown schema ID, or a task/artifact binding mismatch never reaches the model.

IMPLEMENTED

Deterministic, complete-or-fail context

Context is stateless per case. Quantitative tasks materialize frozen typed facts. Narrative retrieval is frozen upstream with candidate_k=15; planning receives no evidence chunks, and load_frozen_evidence returns the ordered top-five scope exactly once for synthesis. Both paths admit zero through five evidence items.

There is no vector database, cross-case memory, autonomous delegation, or LLM summarization layer.

IMPLEMENTED

Three unambiguous runtime modes

direct

The model receives frozen facts or evidence and produces a terminal proposal without tools. Quantitative prompts include the registered metric operation contract so formula conventions are explicit. The verifier independently recomputes or replays the operation.

capability_agent

The model proposes the exact registered action, receives its typed observation, and then produces a terminal proposal. Stage schemas prohibit terminal actions during planning and prohibit tool calls during synthesis.

safety_hybrid

This is the deployable baseline. Routing is deterministic. Quantitative tool results become verifier-checked answers or refusals without model synthesis. Narrative generation selects one to three exact quotes after the frozen scope is loaded; the runtime derives all released prose, claims, and citations.

Safety-hybrid quantitative records carry no model configuration or model tokens; they bind the deterministic executor and operation-registry hashes instead. Results are reported separately by task family and mode.

IMPLEMENTED

One repair, only with safe diagnostics

The repair budget is global to the case, not one attempt per stage. A repair request is legal only when a repair remains and at least one failure has an allowlisted, non-target-sensitive diagnostic.

RepairableTerminal and non-repairable
Malformed JSON; public schema syntax; action-shape errors; canonical decimal/unit lexical form.Gold/target-sensitive comparisons; evidence, citation, arithmetic, refusal, cross-task, observation-binding, prompt-injection-policy, and integrity failures.

For mixed failures, the prompt receives only safe diagnostics. If filtering leaves no diagnostic, the runtime returns MODEL_FAILURE without calling the repair prompt builder and without incrementing repair_count. A repaired output is verified once; failure is terminal and no second repair path exists.

IMPLEMENTED

Independent deterministic release verification

Quantitative

Check task/filing/period/unit/context/dimensions, registered formula, typed inputs, sign, canonical value, exact unit, and answer-to-evidence mapping. The release check recomputes the metric instead of trusting the agent's observation.

Narrative

Check filing and scope membership, stable replay, extractive answer text, claim-level evidence, and contiguous supporting text. This proves support within cited evidence, not filing-wide semantic completeness.

Release invariant. A model proposal can emerge only as a verified answer, a policy-safe refusal, or an explicit typed failure. A second LLM is never a release gate.

TOOL_CALL_APPROVED, REPAIR_REQUIRED, and verifier FAILED remain local verifier trace states. They are not legal terminal outcomes. FailureV2 records a registered class, code, stage, retryability, and sanitized detail without raw exceptions or environment data.

Complete model-request and run identity

Canonical form

Every hash-bearing object uses auditops.canonical_json.v1: compact sorted-key UTF-8 JSON with NaN, infinity, and non-string mapping keys rejected. AuditOps does not claim RFC 8785/JCS compliance.

Per-call request envelope

The envelope excludes the generated request ID and binds its version, stage, repair attempt, ordered messages, full response schema, maximum output tokens, normalized sampling, seed, prompt version, and portable semantic model configuration. Every attempt records request_sha256 and response_schema_sha256.

Run envelope

After context construction, the runtime binds runtime, prompt, and canonicalization versions; task/input hash; corpus and benchmark; runtime mode and prompt condition; context hash; stage-schema bundle hash; and semantic-model hash. run_id is run- plus the first 24 hexadecimal characters of run_envelope_sha256.

The portable semantic model hash excludes model_path. deployment_model_config_sha256 binds the complete config, including that local path, while the exact snapshot digest remains provenance. Moving identical pinned weights does not change semantic run identity.

IMPLEMENTED

Immutable batch, checkpoint, and replay behavior

  • Every expected case produces one immutable result or one typed failure; no case is silently dropped.
  • Resume is allowed only when benchmark, task membership, model, prompt, runtime, schema bundle, and context bindings match.
  • Existing results are never silently overwritten.
  • Verifier replay recomputes the registered operation from model-visible cases and evidence, not from gold.
  • Credential and target/gold scans are hard gates for retained source, prompts, traces, and reports.

Sampling is locked to temperature=0, top_p=1, and seed 20260821. Planning is capped at 192 tokens, quantitative synthesis and repair at 256, and narrative synthesis and repair at 768. Each attempt records its response-schema hash, constraint backend, finish reason, token counts, output bytes, cap-hit status, and sanitized parse category. The runtime fails closed when structured decoding is unavailable and never retains real filing completions.

Few-shot requests use exactly four approved examples from the current task family. Their rendered message block is capped at 3,200 tokens under both pinned tokenizers and is bound to a human-review packet; unapproved examples cannot run.

IMPLEMENTED

VLM runtime stays separate

The text runtime rejects vlm_diagnostic. Image-PDF diagnostics use VlmDiagnosticTaskV1, VlmDiagnosticResultV1, and the isolated VLM runtime. Page/extraction results are evaluated separately and never merged into the US or UK XHTML text benchmark score.

PROPOSED

Possible extension

A future cross-language replay requirement may warrant a standards-conforming canonicalization scheme. It requires explicit compatibility vectors and a new version; it is not implied by v2.2.

DEFERRED

Outside this runtime

Human escalation, genuine PCAOB/ISA procedures, audit opinions, professional judgment, fraud and going-concern determinations, fine-tuning, live APIs, vector memory, autonomous swarms, and external actions are deferred. Advisory model uncertainty does not create an ESCALATED outcome.
